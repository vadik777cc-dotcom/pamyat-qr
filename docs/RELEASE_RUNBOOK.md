# Release runbook — Память QR

## 1. Подготовка окружения

```bash
cp .env.example .env
npm install
npm run seed
npm run check
```

В `.env` обязательно задать:

- `SESSION_SECRET`;
- production URL;
- настройки HTTPS/proxy;
- путь к постоянному хранилищу файлов, если он отличается от локального.

## 2. Быстрый прогон после обычной сессии

```bash
rm -rf playwright-report test-results
npm run test:e2e
npm run test:debug-pack
```

## 3. Полный прогон перед релизом

```bash
rm -rf playwright-report test-results
npm run check
npm run test:e2e:full
npm run test:debug-pack
```

Полный прогон нужен:

- перед показом клиенту;
- перед выкладкой на сервер;
- после изменений ролей, invite, прав доступа, публикации, QR, backup.

## 4. Что проверить вручную

- Вход платформы.
- Создание партнёра.
- Создание бизнеса.
- Генерация invite-ссылки.
- Активация клиента через invite.
- Повторное использование invite заблокировано.
- Создание страницы памяти.
- Публикация страницы.
- Открытие публичной страницы на телефоне.
- Скачивание QR.
- Открытие B2C-лендинга на телефоне.
- Партнёр не видит чужие бизнесы.
- Бизнес не видит платформенные страницы.

## 5. Что отправлять при ошибке

Если тест падает:

```bash
npm run test:debug-pack
```

Отправить архив `session-debug-light.zip` вместе с текстом ошибки.

## 6. Критерий готовности к первому клиенту

Можно подключать первую компанию, если:

- короткий прогон проходит 10/10;
- полный прогон проходит без failed;
- публичные страницы открываются без 404/500;
- demo-текст на login скрыт;
- клиентская активация идёт через invite;
- права доступа проверены.
