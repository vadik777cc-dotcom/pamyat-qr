# Чеклист подключения первой ритуальной компании

## До подключения

- Проверить `SESSION_SECRET` в `.env`.
- Проверить HTTPS/Nginx на сервере.
- Проверить постоянное хранилище `uploads`.
- Проверить резервное копирование базы и файлов.
- Запустить полный прогон тестов.

```bash
npm run check
npm run test:e2e:full
npm run test:debug-pack
```

## Создание клиента

1. Войти в платформенную админку.
2. Создать партнёра, если клиент подключается через партнёра.
3. Создать бизнес.
4. Проверить название, город, телефон, email, тариф и статус.
5. Сгенерировать одноразовую ссылку подключения.
6. Передать ссылку клиенту.

## Первый вход клиента

- Клиент открывает invite-ссылку.
- Клиент задаёт пароль самостоятельно.
- Клиент попадает на экран «Первый запуск».
- Повторное использование ссылки должно быть заблокировано.

## Проверка после входа

- Клиент видит только свою бизнес-админку.
- Клиент не видит платформенные разделы.
- Клиент не видит чужие бизнесы.
- Партнёр видит только свои бизнесы.
- Партнёр не может удалить бизнес.
- Супер-админ видит все бизнесы и аналитику.

## Минимальная настройка бизнеса

- Заполнены название, город и телефон.
- Настроен лендинг для семей.
- Создана первая страница памяти.
- Страница опубликована.
- QR-код сформирован.
- Публичная ссылка открывается на телефоне.

## Перед передачей клиенту

- На странице входа нет демо-подсказок.
- На публичном лендинге нет сырого CSS/служебного текста.
- На странице памяти нет технических слов.
- На адресной странице нет DNS/CNAME в основном интерфейсе.
- Быстрый старт скрывается после завершения начальной настройки.
