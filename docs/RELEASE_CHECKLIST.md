# Release checklist — Память QR

Финальная проверка перед показом продукта ритуальной компании.

## 1. Техническая проверка

```bash
npm install
npm run seed
npm run check
npm run test:e2e
npm run test:e2e:full
npm run test:debug-pack
```

Короткий прогон используется после каждой сессии. Полный прогон запускается перед демонстрацией клиенту, перед выкладкой и после крупных изменений прав доступа.

## 2. Безопасность

- `SESSION_SECRET` задан и не равен dev-значению.
- Клиенты подключаются через одноразовую invite-ссылку.
- Пароль задаёт клиент, пароль не передаётся вручную.
- Invite-ссылка действует 24 часа и блокируется после первого использования.
- Платформа и партнёр видят только свои бизнесы по scope.
- Имперсонация логируется.
- CSRF и same-origin проверки включены.

## 3. Первый клиентский сценарий

1. Платформа или партнёр создаёт бизнес.
2. Генерируется ссылка подключения.
3. Клиент открывает ссылку и задаёт пароль.
4. Клиент попадает на экран «Первый запуск».
5. Клиент заполняет компанию, лендинг, страницу памяти.
6. Клиент публикует страницу и получает QR.

## 4. Демонстрация

Показывать клиенту только понятные сценарии:

- как создать страницу памяти;
- как добавить фото и текст;
- как опубликовать;
- как скачать QR;
- где смотреть заявки семьи;
- где открыть публичный лендинг.

Не показывать без необходимости технические разделы: Health, Audit, резервные копии, SEO, доменные настройки.

## 5. Перед первой продажей

- Проверить публичный лендинг на телефоне.
- Проверить страницу памяти на телефоне.
- Проверить QR-скачивание.
- Проверить, что на странице входа нет демо-подсказок.
- Проверить, что партнёр не может управлять чужими бизнесами.
- Проверить, что бизнес не видит платформенные страницы.
